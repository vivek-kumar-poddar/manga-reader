# RE-CODE PLAN - MANGA READER

Basis: Space-agency-inspired engineering principles (predictable execution, bounded resources, explicit ownership, failure recovery, traceable verification).

HOW TO USE
- Order: Read `migrate-to-rust.txt` first, then this file.
- Status: [COMPLETED] = verified; [IN PROGRESS] = partial; unmarked = pending.
- Current Status: Steps 01–17 [COMPLETED]; Steps 18–22 pending.
- Invariant: Work through numbered steps in order; land small reviewable changes. Mark [COMPLETED] only after automated acceptance checks pass. Update `docs/verification.md` with evidence.

CRITICAL ARCHITECTURAL INVARIANTS:
1. No custom protocol schemes (e.g. `manga://`). Use verified IPC (`read-file` / Tauri bridge). Custom schemes break Chromium's `file://` security context and LevelDB/IndexedDB backing store.
2. Single-instance process lock to prevent concurrent LevelDB corruption.
3. Strict bounds on native file access: 100 MiB file ceiling, depth <= 64, <= 100,000 files, allowlisted image extensions only.
4. Preserve existing user IndexedDB data, reading progress, and settings schema across all refactors.

## Key Architectural Invariants & Rules

1. **State & Persistence**:
   - Save reading progress continuously with transactional durability. Never rely on `beforeunload` or asynchronous shutdown events.
   - Database writes must be atomic per title. Aborted transactions must leave caller memory and storage untouched.
   - Do not replace sequential async operations with unbounded `Promise.all` or `forEach`.

2. **Memory & Lifecycle**:
   - Every `ImageBitmap` must be closed in a `finally` block (`bitmap.close()`).
   - Canvases must reset dimensions (`width = 0; height = 0`) on disposal.
   - Off-screen images must cancel loading immediately via `AbortController`.
   - Polling loops are strictly prohibited; use event-driven reactive wakeups.

3. **Validation & Boundaries**:
   - Accept `unknown` at boundaries; validate types, bounds, finite numbers, and integers before use.
   - Never use TypeScript `as` casting as a substitute for runtime validation.
   - Path traversal (`../`), null roots, duplicate IDs, and NaN values must be rejected before storage transactions.
